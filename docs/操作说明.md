# 操作说明

> 本文档是给项目 owner 的快速上手手册，不是 AI 的工作规则。AI 的规则在 `AGENTS.md` 和 `docs/` 下的各类 spec / pattern 里。
> 5 分钟读完就敢开口。需要细节时再翻 `docs/request-guide.md`。

## 30 秒认知

这是 CS2 物品市场监控平台。和 AI 协作的核心模式：**你说一句话 → AI 自己判断改动大小（A/B/C/D）→ 走对应流程**。你不需要主动指定类型，AI 会判，判错了你纠正即可。

## 第一句话怎么说

直接说事，不要绕弯。下面三种最常见：

- **修一个小问题**：「修复 RecommendationsPage 里日期格式错位的 bug」
- **加一个功能**：「我想给推荐池加一个二级筛选，按磨损区间过滤」
- **改文档/进度**：「更新 progress.md，把 US-007 标记为完成」

AI 会自己判类型，然后回你一份 plan。你看完点头（"ok / 可以 / 干吧"）它才动手。

## AI 工作时的几个状态

知道它现在在哪一步，你就知道现在该回什么：

1. **读文档** — AI 在看 AGENTS / progress / architecture，不用管它
2. **出 plan** — 给你目标、改哪些文件、风险、验收标准。**你要 ack**（同意/调整/打回）
3. **编码中** — 它在改代码，等就行
4. **跑三件套** — `tsc --noEmit` / `npm test` / `npm run build`，等结果
5. **等 commit** — 三件套绿了，它会问"要不要 commit"，**你不说它不会自己提交**
6. **等 push** — commit 完了，它会问"要不要 push"，同上

记住：**commit 和 push 都需要你显式说**。AI 不会自作主张。

## 最常用 5 句话

- 「按 A 类小修复处理」/「按 B 类中改动处理」— 强制指定类型
- 「ok，干吧」/「这个 plan 可以」— ack 一份 plan，让它进入编码
- 「先别 commit，我再看看」— 暂停在三件套之后
- 「commit 并 push」— 一次性走完
- 「这个改动有点大，先填 01-scenario-alignment 模板」— 把模糊需求拉回正轨

## 出错救火

- **AI 类型判错了**（比如把一个加功能当小修复）：直接说「这不是 A，是 B，重新走流程」，它会回到出 plan 那步
- **AI 没等你 ack 就 commit 了**：说「revert 上一个 commit」或「git reset 到上一个 commit」。然后提醒它"未经 ack 不要 commit"
- **AI 改了你没要求改的文件**：说「把 XX 文件的改动还原，只保留 YY 的修改」。如果已经 commit，让它 revert 或新开一个 commit 撤回多余改动
- **AI 卡在出 plan 反复确认**：说「不用再确认了，直接按你刚才的 plan 干」
